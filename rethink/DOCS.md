# LG ThinQ Local: установка и эксплуатация

Приложение упаковывает [Rethink](https://github.com/anszom/rethink) для Home
Assistant OS. Rethink подменяет облачную точку подключения совместимых устройств
LG ThinQ и переводит их локальный протокол в MQTT Discovery Home Assistant.

## Архитектура

```text
                         ┌─────────────────────────────┐
Устройство LG ThinQ2 ───>│ LG ThinQ Local              │
  HTTPS/TCP 443          │ Rethink Cloud               │───> MQTT-брокер
  MQTT TLS/TCP 8883      │ CA, ключи и state в /data   │     TCP 1883
                         └─────────────────────────────┘
                                      │
                                      └── Home Assistant Ingress
                                          внутренний TCP 44401
```

Один экземпляр приложения может обслуживать несколько совместимых устройств.
Для каждого кондиционера не нужно создавать отдельное приложение или отдельного
пользователя MQTT.

## Требования

- Home Assistant OS или Supervised на `amd64`;
- установленный MQTT-брокер и отдельные учётные данные для приложения;
- локальный DNS с возможностью создавать A-записи;
- маршрутизация из сегмента техники к IP Home Assistant по TCP `443` и `8883`;
- свободные TCP-порты `443` и `8883` на узле Home Assistant.

## Установка из репозитория

1. Откройте **Настройки → Приложения → Магазин приложений**.
2. В меню репозиториев добавьте:

   ```text
   https://github.com/akinin/rethink-home-assistant-app
   ```

3. Обновите список, откройте **LG ThinQ Local** и установите приложение.
4. Заполните параметры MQTT и запустите приложение.
5. Проверьте журнал до подключения техники.

## Параметры

### Сервер Rethink

| Поле | Рекомендуемое значение | Назначение |
| --- | --- | --- |
| `hostname` | `rethink.lan` | Имя локального сервера, которое получат устройства |
| `management_port` | `44401` | Внутренний порт интерфейса Ingress |

### MQTT

| Поле | Пример | Назначение |
| --- | --- | --- |
| `host` | `<Home Assistant IP>` | Адрес MQTT-брокера |
| `port` | `1883` | Порт локального MQTT |
| `username` | `lg_thinq_local` | Отдельный пользователь приложения |
| `password` | — | Пароль MQTT; не публикуйте его в Git |

### Дополнительно

Значения `discovery_prefix: homeassistant` и `rethink_prefix: rethink` обычно
менять не требуется. Изменение префиксов создаст новые MQTT-топики и может
привести к дублированию сущностей.

## DNS: постоянная и временная записи

### Постоянная запись

```text
Тип: A
Имя: rethink.lan
Адрес: <IP Home Assistant>
TTL: 300
```

Эта запись используется уже зарегистрированными устройствами для повторного
подключения к локальному серверу и должна оставаться постоянно.

### Временная запись для регистрации ThinQ2

```text
Тип: A
Имя: common.lgthinq.com
Адрес: <IP Home Assistant>
TTL: 300
```

Она перехватывает только этап получения маршрута во время первичной регистрации.
После появления устройства в Rethink удалите запись, чтобы другие клиенты сети
не обращались к локальному серверу вместо настоящего домена LG.

### Что означает TTL 300

TTL задаётся в секундах. `300` означает, что шлюз, клиент или устройство может
хранить старый DNS-ответ до пяти минут. Поэтому:

- после добавления или изменения записи подождите до пяти минут;
- для немедленной проверки переподключите Wi-Fi устройства;
- при откате сначала измените A-запись, затем переподключите устройство;
- значение `Авто`, если шлюз не показывает фактический срок, хуже для временной
  записи: оно может означать час или сутки;
- слишком большой TTL усложняет регистрацию и откат, а TTL `0` поддерживается
  не всеми IoT-клиентами; `300` — безопасный практический компромисс.

Проверка с компьютера в той же сети:

```bash
dig +short rethink.lan
dig +short common.lgthinq.com
```

Обе команды во время регистрации должны вернуть IP Home Assistant. После
регистрации вторая запись должна снова разрешаться штатным DNS или отсутствовать
в локальной зоне.

## Подключение первого или дополнительного устройства

Для Android 8.0 и новее можно использовать официальный компаньон **Rethink
Setup**. Проверенная копия v1.1.1 и контрольная сумма находятся в каталоге
[`apk/`](https://github.com/akinin/rethink-home-assistant-app/tree/main/apk).
Приложение позволяет проверить перенаправление DNS и повторяет процедуру
`rethink-setup` прямо на телефоне или планшете.

1. Убедитесь, что приложение запущено и MQTT подключён.
2. Временно направьте `common.lgthinq.com` на IP Home Assistant с TTL `300`.
3. Переведите устройство в режим настройки Wi-Fi согласно его инструкции.
4. Подключите телефон или планшет к Wi-Fi устройства (часто `LG_Smart_*` или
   `LGE_*`). Отсутствие интернета в этой сети нормально.
5. Выполните процедуру **Provision a device** в интерфейсе настройки Rethink.
6. Верните телефон в домашнюю сеть и дождитесь устройства в интерфейсе Rethink.
7. Проверьте появление MQTT-сущностей в Home Assistant.
8. Удалите временную запись `common.lgthinq.com`.
9. Создайте резервную копию Home Assistant.

Для второго кондиционера повторяются только шаги 2–9. Сервер, постоянная запись
`rethink.lan`, MQTT-пользователь и приложение остаются прежними.

## Сеть и безопасность

| Направление | Порт | Назначение |
| --- | --- | --- |
| устройство → Home Assistant | `443/tcp` | локальный ThinQ2 HTTPS |
| устройство → Home Assistant | `8883/tcp` | локальный ThinQ2 MQTT TLS |
| приложение → MQTT-брокер | `1883/tcp` | MQTT Discovery и состояния |
| Home Assistant → приложение | `44401/tcp` | Ingress, только внутренняя сеть Apps |

Не публикуйте `44401` через Nginx Proxy Manager: интерфейс уже защищён сессией
Home Assistant Ingress. Ограничьте `443/8883` сегментом IoT и локальными сетями.
Используйте отдельного MQTT-пользователя с уникальным паролем.

## Постоянные данные и резервные копии

В `/data` хранятся:

- `ca.key` — закрытый ключ локального центра сертификации;
- `ca.cert` — сертификат CA;
- `state/` — сведения и состояние зарегистрированных устройств;
- `config.json` — сгенерированная конфигурация приложения.

Эти данные сохраняются при обновлении. Не переносите только контейнер без `/data`:
устройства доверяют именно созданному CA. Сделайте полную резервную копию Home
Assistant после каждого нового подключения.

## Обновление

Перед обновлением:

1. создайте резервную копию Home Assistant;
2. ознакомьтесь с `CHANGELOG.md`;
3. проверьте, что приложение снова запустилось и подключилось к MQTT;
4. дождитесь автоматического переподключения техники — включать кондиционер для
   этого не требуется.

Базовый образ Rethink закреплён по digest в `Dockerfile`. Обновление upstream
выполняется осознанно новой версией этого приложения, а не автоматически.

## Диагностика

```bash
ha apps info local_lg_thinq_local
ha apps logs local_lg_thinq_local
ha apps restart local_lg_thinq_local
```

Проверьте по порядку:

1. DNS возвращает IP Home Assistant;
2. firewall разрешает `443/tcp` и `8883/tcp`;
3. в журнале нет ошибки авторизации MQTT;
4. порты не заняты другим приложением;
5. после изменения DNS истёк TTL либо Wi-Fi устройства переподключён.

## Откат

1. Остановите **LG ThinQ Local**.
2. Верните `rethink.lan` на адрес предыдущего сервера.
3. Запустите предыдущий сервер с теми же `ca.key`, `ca.cert` и `state`.
4. Переподключите устройство к Wi-Fi или дождитесь следующей попытки.

Нельзя одновременно запускать два сервера с одним DNS-именем и разными CA.

## Ограничения и ответственность

Текущая упаковка ориентирована на ThinQ2 и `amd64`. Поддержка функций зависит
от модели и профиля устройства. Rethink и это приложение не связаны с LG
Electronics. Не используйте отправку сырых пакетов без понимания протокола.
